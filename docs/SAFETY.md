# Safety analysis vs. the hackathon red lines

| Red line (announcement) | AgentPay ID position |
| --- | --- |
| No web QR-code / pairing-code login for Agentic Wallet; no storing user sessions on a server to act for the user | Login is the wallet's own injected provider only. No server exists in this project at all (static frontend). No sessions are stored anywhere. |
| Skills/prompts must not bypass user transaction confirmation | Every asset movement is a normal on-chain transaction the user reviews (amount + recipient) and confirms in their wallet. The frontend code contains no auto-sign path. |
| No unauthorised asset transfers: no scheduled collection, no transfers to fixed addresses, no bundled extra transfers, no unlimited approvals | `payBNB` forwards exactly `msg.value` to the caller-named recipient, same transaction, zero fee. `payToken` moves exactly the stated amount. Frontend requests ERC-20 approval for the exact amount only. No cron/scheduled code exists. |
| Contracts open-source, owner permissions disclosed | Single-file MIT contract, published in this repo and verified on BscScan. Owner can only pause/unpause this contract's interactions and transfer ownership — documented in README and in the contract header. No mint, no tax change, no pause-trading of any token, no freezing, no withdrawal function. |
| No impersonation of the Binance brand | Product name is "AgentPay ID". No Binance/BNB word or logo in name, token (there is no token), or domain. |
| No collection of sensitive credentials | The dApp never asks for seed phrase, private key, API secret, or pairing code; the page states this explicitly. Deploy keys live only in a local `.env` (git-ignored). |
| Must not promise returns ("passive income", "automatic money-making") | No such language anywhere. Reputation points are declared valueless, non-transferable, and not a token. |
| Trading products must display risk warnings | Not a trading product, but the payment page still displays an irreversibility warning and the README carries a risk warning. |
| Agent ID must not be packaged as a tool for looking up other people's wallets by name | There is no name→address lookup or directory. Payment links are self-generated by the recipient for their own address. Enforced by `test/logic-test.js` (fails if `handleOf`/`agentOf`/resolver names appear in the contract). |
| No malicious volume / mass-account manipulation | Growth comes only from real holders checking in / paying. `uniqueInteractors` counts genuine Agent ID holders; no sybil tooling is built or used. |

## Residual risks (honest list)

- Contract is not third-party audited (hackathon scope) — mitigated by a
  deliberately tiny surface: one file, no dependencies, no custody, no
  upgradeability, reentrancy-safe payment pattern (state updated before the
  external call in `payBNB`; `payToken` relies on standard ERC-20
  `transferFrom` semantics — unusual tokens with callbacks are out of scope
  and the UI launches with BNB payments only).
- `payBNB` forwards to a recipient that may be a contract wallet; if the
  recipient rejects BNB the transaction reverts and the sender keeps funds.
